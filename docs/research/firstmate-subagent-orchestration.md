# FirstMate as a source of subagent-orchestration ideas

## Scope and pinned source

I inspected FirstMate at commit [`355f46fe5528ccc9790481171bf9da48dee2e90d`](https://github.com/kunchenguid/firstmate/tree/355f46fe5528ccc9790481171bf9da48dee2e90d), the `main` tip on 2026-09-01. All FirstMate source links below pin that commit. I used the repository, its GitHub metadata, and the official Pi repository only. Claims marked **undocumented observation** come from repository or GitHub state rather than a stated FirstMate contract.

## 1. What it is, installation, invocation, and maturity

FirstMate is an "agent distro": a cloned directory of `AGENTS.md`, skills, shell scripts, policies, and local state conventions. It is not an agent model, MCP server, standalone CLI, or daemon product. A supported coding-agent harness launched in the clone reads the instructions and becomes the coordinator. The coordinator delegates work to autonomous harness processes in visible terminal/session-manager endpoints and isolated worktrees ([README.md L27-L40](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L27-L40)).

Installation is `gh auth login`, clone the repository, enter it, then run `claude`, `grok --trust`, or `pi`. Pi requires one project-trust approval so the tracked extensions load ([README.md L57-L66](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L57-L66), [L79-L110](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L79-L110)). It supports macOS and Linux, with tmux as the reference runtime backend ([README.md L59-L64](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L59-L64)). The license is MIT ([LICENSE L1-L20](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/LICENSE#L1-L20)).

Maturity is mixed. The tmux path is called the verified reference, while Herdr, Zellij, Orca, and cmux are explicitly experimental ([docs/configuration.md L110-L129](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L110-L129)). The repository has a large, carefully partitioned shell test suite and opt-in live backend/harness tests ([CONTRIBUTING.md L76-L116](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/CONTRIBUTING.md#L76-L116)). **Undocumented observation:** at inspection time GitHub showed no tags and no releases ([tags](https://github.com/kunchenguid/firstmate/tags), [releases](https://github.com/kunchenguid/firstmate/releases)); the pinned tip was an active fix commit ([commit](https://github.com/kunchenguid/firstmate/commit/355f46fe5528ccc9790481171bf9da48dee2e90d)). This looks like an actively developed operator template, not a versioned stable product.

## 2. Architecture

### Coordinator, workers, and backends

The coordinator is the primary coding agent following `AGENTS.md`; deterministic scripts perform state transitions, while the agent makes intake and dispatch judgments. FirstMate deliberately keeps those roles separate ([VISION.md L37-L45](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/VISION.md#L37-L45)). Each worker is another interactive coding-agent process with a task brief, one endpoint, and normally one disposable worktree ([README.md L136-L162](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L136-L162)).

FirstMate has two separate adapter axes:

- The **agent harness** is Claude, Codex, OpenCode, Pi, `pi-signed`, Grok, Kimi, Cursor, or Muse. The coordinator can select a harness, model, and effort per task; scripts validate the concrete choice but leave natural-language rule matching to the coordinator ([docs/architecture.md L222-L231](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L222-L231)).
- The **runtime backend** owns endpoint creation, capture, input, path lookup, liveness probes, and teardown. tmux is the reference adapter; Herdr, Zellij, Orca, and cmux are alternatives ([docs/architecture.md L166-L190](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L166-L190)).

There is no provider SDK or provider-level scheduler in FirstMate. Provider and model handling stays inside the selected harness; `fm-spawn.sh` passes only supported model/effort flags ([bin/fm-spawn.sh L35-L40](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L35-L40)).

### Queue, state, messaging, and results

`data/backlog.md` is the durable work queue. It records work, dependencies, holds, and history, not agent processes. The coordinator re-evaluates it after teardown and heartbeats and dispatches only work whose dependency and time gates have cleared ([AGENTS.md L495-L505](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L495-L505)). `tasks-axi` normally mutates the Markdown queue; spawn and teardown pair backlog transitions with task-record creation/removal so those two records cannot drift on the successful path ([docs/configuration.md L91-L108](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L91-L108)). This is a dependency-aware queue, not a general DAG executor. Dispatch choice remains agent judgment ([AGENTS.md L300-L308](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L300-L308)).

State is plain, gitignored disk data. `data/` holds backlog, briefs, reports, preferences, and registries; `state/` holds task metadata, append-only status events, turn-end markers, durable inboxes, wake queues, locks, and recovery receipts ([AGENTS.md L43-L54](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L43-L54), [L83-L134](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L83-L134)).

Messaging has two planes. `fm-send` writes the full text atomically into a sequenced per-task inbox, then sends a constant terminal "doorbell"; the worker acknowledges by moving the record to `handled/`. Unacknowledged messages are re-rung on a bounded schedule and then escalated ([bin/fm-task-inbox-lib.sh L14-L56](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-task-inbox-lib.sh#L14-L56)). `fm-control` separately permits only `interrupt`, `exit`, and `relaunch`, addressed to an exact task id ([docs/agent-control.md L3-L24](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L3-L24)).

Workers append status-event lines. A reconciler, rather than the latest prose line, derives current state. Scout results are standalone `data/<id>/report.md` files; ship results are PRs or approved local merges ([docs/architecture.md L57-L79](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L57-L79), [L219-L220](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L219-L220)).

### Monitoring, UI, and hooks

A Bash watcher classifies status, authenticated checks, stale endpoints, and heartbeats without spending model tokens. It appends actionable items to a durable wake queue; the primary session drains and acknowledges them ([docs/architecture.md L9-L27](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L9-L27), [AGENTS.md L167-L180](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L167-L180)). Harness hooks or extensions report semantic turn lifecycle. Pi uses FirstMate-owned `agent_start` and `agent_settled` events; Codex lacks a verified semantic busy source and is classified as unknown until stronger evidence exists ([docs/architecture.md L148-L160](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L148-L160)).

The UI is the coordinator chat plus visible worker tmux windows, Herdr/Zellij tabs, cmux workspaces, or Orca terminals. Operators may inspect or type into those endpoints ([README.md L42-L50](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L42-L50)). On a Pi primary, a second persistent in-process conversation can absorb routine supervision and append outcomes back to the main conversation ([docs/pi-supervision-branch.md L8-L19](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/pi-supervision-branch.md#L8-L19)). That branch is supervision machinery, not a worker pool.

### Worktrees and branches

Ship and scout workers must run in a real git worktree distinct from the primary checkout. Treehouse supplies pooled worktrees for all session backends except Orca, which owns its worktrees; spawn fetches and resets a clean new worktree to the remote default tip and refuses unsafe or unverifiable bases ([docs/architecture.md L192-L197](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L192-L197), [bin/fm-spawn.sh L135-L149](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L135-L149)). Teardown refuses dirty or unlanded ship work and requires a scout report before discarding scout scratch state ([bin/fm-teardown.sh L22-L46](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-teardown.sh#L22-L46)).

## 3. Agent lifecycle and durability

- **Spawn and name.** `fm-spawn.sh <task-id> ...` is the only launch owner. It accepts ship, scout, and persistent secondmate shapes ([bin/fm-spawn.sh L1-L34](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L1-L34)). The task id binds metadata to its opaque endpoint, while visible aliases use `fm-<id>` where supported ([docs/configuration.md L130-L136](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L130-L136)). Every spawn records a fresh incarnation token so stale events from a replaced process do not count ([bin/fm-spawn.sh L188-L207](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L188-L207)).
- **Monitor.** Semantic lifecycle records classify `busy`, `idle`, `unknown`, or `dead`; missing or stale evidence remains unknown rather than guessed idle ([docs/architecture.md L148-L162](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L148-L162)). A several-hour busy turn eventually raises an inspection wake, but FirstMate never auto-interrupts or auto-restarts it ([docs/architecture.md L12-L19](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L12-L19)).
- **Interrupt and exit.** Per-harness tables define the cancel key, repeats, exit command, and observable acknowledgement. Unsupported combinations fail closed ([bin/fm-control-lib.sh L109-L165](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-control-lib.sh#L109-L165)). Exit preserves the endpoint, worktree, and uncommitted changes ([docs/agent-control.md L29-L48](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L29-L48)).
- **Resume and retry.** FirstMate has no `resume` control verb. Its maintainers explicitly say Pi has no verified pane-resume contract in this system. Instead, `relaunch` starts a new conversation in the same endpoint/worktree from the durable brief plus a required progress note for ship/scout tasks ([docs/agent-control.md L50-L72](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L50-L72)). Relaunch is journaled and restores prior metadata if launch fails before publication ([docs/agent-control.md L76-L81](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L76-L81)). A selected backend spawn failure is surfaced, never retried on another backend ([docs/configuration.md L126-L129](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L126-L129)).
- **Cleanup.** Cleanup is explicit and separate from process control. It verifies landed work or explicit discard authority, closes the exact endpoint, returns/removes the worktree, clears volatile state, and closes the backlog item with a crash-recovery receipt ([bin/fm-teardown.sh L1-L21](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-teardown.sh#L1-L21), [L76-L79](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-teardown.sh#L76-L79)).

The durability distinctions matter:

1. **Conversation persistence.** Pi's supervision branch stores its own conversation, pointer, mirror cursor, and append-only outcomes on disk ([AGENTS.md L111-L114](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L111-L114)). Ordinary worker conversation resumption is not FirstMate's recovery contract.
2. **Live-process durability.** A tmux or other backend endpoint can outlive the coordinator terminal/session, and startup reconciles disk state with backend state ([README.md L49-L53](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L49-L53)). This does not make an agent process immortal.
3. **Host-restart recovery.** Durable briefs, metadata, inboxes, and backlog survive. Confirmed-dead or missing persistent secondmates are relaunched at startup; ambiguous endpoints are preserved ([AGENTS.md L163-L171](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L163-L171)). **Undocumented for ordinary workers:** I found no contract that automatically relaunches dead ship/scout agents after a host restart. The documented general recovery is manual `relaunch`, with a new conversation.

## 4. Direct Pi support

Yes. This is explicit source, not inference. `pi` and `pi-signed` are verified harness names ([bin/fm-control-lib.sh L61-L69](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-control-lib.sh#L61-L69)). `fm-spawn.sh` has a Pi launch template that invokes the resolved Pi executable, loads a per-task extension for ordinary workers, and loads watcher plus turn-end extensions for secondmates ([bin/fm-spawn.sh L1221-L1250](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L1221-L1250)). `config/crew-harness` and `config/secondmate-harness` may select Pi, with per-task `--harness pi` overriding configuration ([docs/configuration.md L310-L325](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L310-L325)). This is direct Pi-process launch, not merely support for Codex/Claude-branded workers.

## 5. Fit for ds-mode's required cases

| Required case | FirstMate mechanism | Fit for a small Codex-lead / Pi-worker arrangement |
|---|---|---|
| Parallel read-only investigation | Scout tasks, isolated worktrees, standalone reports ([AGENTS.md L286-L290](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L286-L290)) | The report contract is useful. A mandatory worktree, backlog item, watcher, and teardown per read-only investigation are more than ds-mode needs. |
| One background writer | One named task record, durable brief, Pi process, status/result file | Strong fit conceptually. Keep one writer in the primary checkout only if ds-mode already serializes all mutation; otherwise use one worktree. |
| Occasional worktree writers | Distinct fetched worktrees and fail-closed cleanup ([docs/architecture.md L192-L205](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L192-L205)) | Borrow isolation and exact ownership checks, not Treehouse pooling. Plain `git worktree` is enough at this scale. |
| Independent review | A separate scout/review can be explicitly requested, but FirstMate otherwise avoids stacked manual reviews ([AGENTS.md L321-L327](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L321-L327)) | A fresh read-only Pi review session with the exact diff maps cleanly. |
| Several-hour local task | Persistent endpoint, durable brief/inbox, semantic busy state, bounded stale escalation without automatic kill ([docs/architecture.md L12-L19](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L12-L19)) | Borrow "inspect, never auto-kill" and a process-owned result file. Full heartbeat/wedge machinery is unnecessary initially. |
| Manual process resume | FirstMate relaunches from disk in the same worktree, not from harness conversation state ([docs/agent-control.md L50-L72](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L50-L72)) | ds-mode's proposed named Pi session can do better for manual continuity. Pi officially supports `--name`, `--session`, and session IDs ([Pi README L245-L254](https://github.com/earendil-works/pi/blob/b8b873b9872db04a938fb4357b5e8e824ddc051c/packages/coding-agent/README.md#L245-L254)). Keep a disk brief as the fallback if the process or session is unavailable. |

## 6. Features ds-mode does not need

The following solve cases ds-mode has explicitly removed and should not come along:

- Remote/SSH secondmate homes, cross-home backlog transfer, remote liveness, and route recovery ([docs/architecture.md L233-L258](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L233-L258)).
- A persistent multi-project backlog, dependency scheduling, held decisions, archive retention, and quota-aware dispatch ([AGENTS.md L495-L505](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/AGENTS.md#L495-L505), [docs/architecture.md L222-L231](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L222-L231)).
- PR/CI polling, merge confirmation, automatic merge paths, and teardown tied to forge state ([docs/architecture.md L285-L301](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L285-L301)).
- Relay, X/Discord replies, public follow-up obligations, voice relay, and process-event adapters.
- Second-level coordinators, Pi's supervision branch, away-mode daemon, fleet heartbeat review, and multi-backend UI projection.

Removing those is not a small configuration choice. They account for much of FirstMate's state schema, locking, watcher logic, dependencies, and recovery code.

## 7. Ideas worth borrowing, and traps to avoid

### Borrow

1. **One code-owned task record.** Store task id, repo/worktree, Pi session id/name, PID or endpoint, mode (`read` or `write`), status, result path, and timestamps. FirstMate's `state/<id>.meta` and incarnation token are the useful core ([bin/fm-spawn.sh L2830-L2873](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L2830-L2873)).
2. **Durable brief and result, not agent-authored control state.** Let the agent write the requested report or patch, but let code create task records and change lifecycle states. FirstMate pairs record publication with backlog transition under one lock ([bin/fm-spawn.sh L3100-L3148](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L3100-L3148)).
3. **Separate message and process control.** A prompt is not an interrupt. Use narrow code paths for `send`, `interrupt`, `resume`, and `stop` ([docs/agent-control.md L3-L20](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L3-L20)).
4. **Incarnation identity.** A new process or resumed session gets a generation token so late completion from an old process cannot overwrite current state ([docs/architecture.md L157-L164](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L157-L164)).
5. **Unknown stays unknown.** Do not infer success or idleness from a quiet terminal or stale prose ([docs/architecture.md L150-L160](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L150-L160)).
6. **Cleanup refuses unsafe mutation.** Match an exact task/worktree/session identity and preserve dirty work. Make forced discard a separate explicit operation ([docs/agent-control.md L83-L101](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L83-L101)).
7. **Results before notifications.** Persist the result/status first, then notify the coordinator. FirstMate applies this ordering to branch outcomes and wake recovery ([docs/pi-supervision-branch.md L27-L35](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/pi-supervision-branch.md#L27-L35)).

### Avoid

- Natural-language status logs as primary truth. FirstMate has substantial folding, cursor, divergence, and acknowledgement machinery precisely because append-only agent prose is ambiguous ([docs/architecture.md L57-L74](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/architecture.md#L57-L74)). ds-mode should have the wrapper own `starting/running/exited/failed`, with agent output only as a deliverable.
- A generic backend matrix before a second backend is required.
- Terminal-screen parsing and composer-state heuristics.
- A durable global queue when the coordinator can launch a small known set directly.
- Automatic retries of writing agents. They risk duplicate mutation. Resume or relaunch should remain manual and identity-checked.
- FirstMate's shell surface and universal toolchain. It requires Node, GitHub CLI, no-mistakes, several `*-axi` tools, plus backend-specific software ([docs/configuration.md L378-L395](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/configuration.md#L378-L395)).
- "Confused-agent-grade" locks as a security sandbox. FirstMate explicitly says its Pi branch lease boundary is not adversarial-grade and acknowledges a residual queue race ([docs/pi-supervision-branch.md L32-L42](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/pi-supervision-branch.md#L32-L42)).

## 8. Options and recommendation

| Option | What it buys | Cost and risk |
|---|---|---|
| Direct Codex shell to a named persistent Pi session | The shortest path: launch Pi with a deterministic name/session id, record it, send the brief, and let the operator resume it manually. Pi provides named and specific sessions ([Pi README L245-L254](https://github.com/earendil-works/pi/blob/b8b873b9872db04a938fb4357b5e8e824ddc051c/packages/coding-agent/README.md#L245-L254)). | ds-mode must own a tiny task record and prove how to detect a live process versus a resumable conversation. |
| Adapt a tiny FirstMate concept | Add a small wrapper around the direct path: atomic task metadata, generation token, read/write mode, optional worktree path, result file, exact stop/resume, and safe cleanup. | Some lifecycle code, but no queue, watcher, backend abstraction, or agent-authored status protocol. |
| Use FirstMate itself | Mature handling of many harnesses/backends, remote homes, PR lifecycle, queues, hooks, and crash cases. | It changes the operating model from "Codex leads a few Pi workers" to a fleet distro, requires a large toolchain, creates worktrees for even scouts, and carries many removed features. |

**Recommendation:** choose the second option, implemented as a very thin layer over the first. Do not use FirstMate itself. The valuable FirstMate idea is not fleet orchestration; it is that exact lifecycle state belongs to deterministic code while agents receive briefs and produce artifacts.

A good prototype question is: **Can one Codex shell command launch a named Pi session, return immediately, persist `{task_id, session_id, pid, generation, cwd, mode, result_path}`, and later distinguish `running`, `process gone but session resumable`, and `not recoverable`, without reading terminal pixels or trusting agent-written status?** Test that across normal completion, Ctrl-C of the launcher, killing Pi, and a fresh shell. Add worktree creation only after this works for a writer.

## 9. Security, concurrency, mutation, dependencies, and compatibility

- FirstMate workers run with broad autonomy flags such as Codex `--dangerously-bypass-approvals-and-sandbox`, Claude `--dangerously-skip-permissions`, and Grok `--always-approve` ([bin/fm-spawn.sh L1234-L1258](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L1234-L1258)). Worktree isolation protects repository copies from collision; it does not sandbox the host, credentials, network, or other filesystem paths.
- Project-local hooks/extensions require trust. Pi users approve the clone, after which tracked TypeScript extensions execute ([README.md L101-L115](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/README.md#L101-L115)). ds-mode should avoid generating executable extensions per task unless the direct CLI/session path cannot meet the contract.
- FirstMate serializes same-task spawn, task-record publication, queue mutation, and home ownership. It still documents an accepted race between eligibility recheck and queue drain ([bin/fm-spawn.sh L96-L100](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/bin/fm-spawn.sh#L96-L100), [docs/pi-supervision-branch.md L37-L42](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/pi-supervision-branch.md#L37-L42)). For ds-mode, one lock per task id plus a single-writer repository rule should be enough.
- Parallel writers must not share a checkout. FirstMate's strict worktree guard is sound; ds-mode can apply it only to tasks declared `write`, while read-only agents can share the repository if their tools are actually restricted to reads.
- Exact endpoint identity matters during cleanup. Never kill by a human-readable title alone. Bind PID/session/worktree to the task generation and verify all of them before signalling or deleting.
- Compatibility risk is highest at harness lifecycle seams. FirstMate has per-harness probes, hooks, and live verification because interrupt keys, exit commands, busy signals, model flags, and trust behavior differ ([docs/agent-control.md L14-L27](https://github.com/kunchenguid/firstmate/blob/355f46fe5528ccc9790481171bf9da48dee2e90d/docs/agent-control.md#L14-L27)). A ds-mode prototype should pin and test one Pi version and one launch path before adding abstraction.
- Named Pi conversation persistence and process durability are separate. A valid session file does not prove a live process; a PID does not prove it is still the same task. The wrapper must check both and keep the generation token authoritative.
